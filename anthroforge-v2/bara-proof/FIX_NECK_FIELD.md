# FIX — body.muscle neck field (the `Weight` name miss)

**Status: FIXED at the source, rebuilt, re-gated, downstream refreshed.**
Found by the coupling validation (COUPLING_VALIDATION.md §2.2);
fixed Nov 12, 2026. Originals preserved in
`work/originals-pre-neckfix/` (targets, slider JSONs, `bara_fields.npz`,
`qa_numbers_bara.json`, and the four app instance packs).

## The bug

`build_bara.py` authored the NeckMass component as

```python
M_src += hi_diff("Weight") * (NECK_WEIGHT_VALUE * SK) * neck_gate[:, None]
```

but the HIMBO Vanilla OSD block is named **`HIMBO - BodyWeight 0 to 1`**.
`hi_diff()` returns zeros on a missing block — silently, by design —
so the shipped `body.muscle` contained **no authored neck field at
all**. Every bara neck number was carried by other fields (traps,
frame), and the strongman read a 36.4 cm neck where the recipe
intended ~43 cm.

## The fix

1. `scripts/build_bara.py`: `hi_diff("Weight")` →
   `hi_diff("Weight 0 to 1")` — the exact gated composition the
   script always claimed to run (Weight 0.90, gate h 0.88–1.18,
   r < 0.13–0.20).
2. `hi_diff()` now prints a loud one-time WARNING to stderr for every
   name that resolves to zero. No lookup can silently drop a field
   again.
3. Full rebuild from the fixed source (log:
   `work/build_bara_neckfix.log`), then a quantised-space repair pass
   (below), then downstream regeneration.

The coupling validation's post-hoc derived field predicted
**43.2 cm / M1 0.854** for exactly this fix; the source-level rebuild
lands at 43.01 / 0.853 (the small delta is the full blend + a fresh
repair attenuation vs the validation's torso-only derivation). M1 now
sits at the Sen preset's own read. Shipped-file check: the neck
station re-measured on the shipped combined `.target` with the
build's own loop machinery reads 36.43 cm for the old file (grade
record 36.44 — machinery verified) and **43.01 cm** for the new one.

Cost inside the build: the fold repair now attenuates 556 core verts
(min 0.051) vs 31 before — the restored neck band is steep and needs
it; the achieved girth still lands on prediction.

## Quantised ship gate (house rule: gates run on shipped numbers)

The rebuild was float-clean (0 flips everywhere) but sat **on** the
fold boundary in the neck band, and the `.target` format's 0.1 mm
quantisation pushed it over — the same failure the hyper pass
documented for the coupling targets:

| composition (shipped files) | before repair | after repair |
|---|---|---|
| muscle, macro | 1 flip, −0.0042 | 0 flips, +0.0354 |
| muscle+width, raw | 1 flip, −0.0026 | 0 flips, +0.0215 |
| combined, raw | 3 flips, −0.0371 | 0 flips, +0.0215 |
| combined, macro | 2 flips, −0.0310 | 0 flips, +0.0250 |

Repair: `work/repair_neckfix_quantised.py`, the hyper precedent
verbatim (attenuation in quantised space, judged on the muscle solo
**and** both compositions, both bases, floor min_dot ≥ 0.01).
Converged in 4 rounds; deviation vs the pre-repair muscle field
**max 1.51 mm, RMS 0.055 mm, 87 verts**. Final worst min_dot across
every composition and basis: **+0.0215** (pre-fix shipped baseline
worst was +0.0136). `bara_fields.npz` was updated to the repaired
field (`att_muscle` folded with the repair attenuation), so the app
packs are identical to what ships; `body.bara.strongman.target` was
rebuilt as the sum of the repaired components. Full gate transcript:
`work/gate_check_neckfix.py`; repair report:
`work/neckfix_repair.json`.

Width and tissue were regenerated by the same build (their repairs
are judged over the muscle field): max deviation vs their previous
files 2.80 mm / 63 verts (width) and 0.92 mm / 35 verts (tissue);
their gate margins are unchanged.

## Downstream

- **App instance packs regenerated** (`anthroforge-app/scripts/
  build_instance_packs.py`): all packs pass the app fold gate at +1;
  the muscle pack's `linear` array differs from the old pack by max
  15.36 mm (the neck field; the validation measured the derived
  field's source max as 1.53 cm).
- **App slider records re-wired** (`wire_proof_records.py`): embedded
  QA grades refreshed from the rebuilt proof JSONs; two hardcoded
  prose numbers corrected (M4 1.303, volume +94.2%) and the
  `body.neck.mass` note updated to record that the "cap" was this
  bug. App suite: **87 passed** before and after.
- **Coupling targets NOT regenerated — deliberately.**
  `build_coupling_validation.py` adds its own derived neck field
  (`NECK_EMB`, from the correct block name) on top of the muscle
  substrate; rebuilding the coupling targets against the fixed
  muscle would double-apply the neck. Their shipped numbers stand as
  documented (all comparisons were raw-vs-effective on identical
  builds). If the coupling compositions are ever rebuilt, drop the
  `NECK_EMB` addition first.
- Character presets reference slider ids, not fields — unaffected.
  A future Sen rebuild composes from the fixed targets and picks the
  neck up automatically (Sen's composed geometry on disk predates
  this fix).

## Open finding (flagged, NOT changed)

The new loud warning exposes every other name that resolves to zero
against the Vanilla OSD in the current recipes: **BodyMass,
PecsLower, ArmsDeltsShape, BubbleButt, TorsoShoulderInc,
TorsoMassSmooth, BellySmooth**. Every published bara number was
measured with these at zero — they are part of the as-validated
composition — and several have plausible but unproven alternates
(e.g. PecsLower → PecsLowerSide). Changing any of them is a
re-validation project of its own, not a side effect of this fix.
They are listed here so the decision is explicit and on record.
